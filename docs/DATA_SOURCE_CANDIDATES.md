# ماتریس اولیهٔ منابع داده MarketSage

> وضعیت: نامزدهای فنی بر پایهٔ مستندات عمومی؛ دریافت زنده، آزمون پوشش کامل و مجوز بازتوزیع هنوز تأیید نشده است. هیچ منبعی صرفاً به‌دلیل داشتن API پذیرفته‌شده نیست.

## اصول انتخاب
- منبع اصلی ترجیحاً منتشرکننده یا متولی همان بازار باشد؛ تجمیع‌کنندهٔ ثالث فقط با برچسب منشأ و کنترل مستقل.
- قیمت بازار آزاد، نرخ رسمی، NAV، قیمت پایانی بورس و قیمت صرافی، سری‌های متفاوت‌اند و نباید با هم ادغام شوند.
- برای هر ابزار، شناسهٔ پایدار، ارز/واحد، بازار، زمان ثبت و تقویم معاملاتی ثبت می‌شود.
- هر منبع قبل از دریافت انبوه باید از نظر دسترسی، پوشش تاریخی، محدودیت نرخ، مجوز استفاده و پایداری schema بررسی شود.

## سیاست تعدیل به تفکیک کلاس

### سهام
- raw OHLCV بدون تغییر نگهداری می‌شود.
- وضعیت تعدیل منبع برای هر ستون/نوع تعدیل بررسی می‌شود؛ adjusted close به معنی adjusted OHLC نیست.
- سود نقدی، افزایش سرمایه از محل آورده/سود انباشته، تجزیه/تجمیع و رویدادهای ترکیبی از دادهٔ بازار و افشای رسمی استخراج می‌شوند.
- اختلاف قیمت روز قبل با قیمت مبنای روز رویداد فقط detector است، نه اثبات نوع رویداد یا ضریب.
- خروجی price-adjusted و total-return جدا هستند.

### صندوق و درآمد ثابت
- NAV صدور، NAV ابطال، NAV آماری، قیمت معامله و توزیع وجه نقد، فیلدهای جدا هستند.
- صندوق‌های توزیع‌کنندهٔ سود نیازمند دفتر توزیع و فرض روشن reinvestment برای ساخت total-return NAV هستند.
- تغییر واحد/سرمایه و تغییر ساختار صندوق، event است؛ به تعدیل قیمتی سهام تبدیل نمی‌شود.
- اگر دفتر توزیع یا معنای NAV روشن نباشد، REVIEW_REQUIRED.

### طلا و سکه
- معمولاً corporate-action adjustment ندارند؛ وظیفهٔ اصلی تشخیص تداوم ابزار و هم‌مبنا کردن واحد/مشخصات است.
- طلای ۱۸ عیار، ۲۴ عیار، مثقال، اونس، سکهٔ امامی/بهار آزادی و انواع قطعات، سری‌های جدا هستند.
- تغییر وزن، عیار، ریال/تومان، بازار/منبع یا spread، شکاف ساختاری است؛ نباید با ضریب قیمت تعدیل پنهان شود.

### ارز
- جفت‌ارز، جهت مظنه، واحد پول، ریال/تومان و نوع نرخ (رسمی، توافقی، نیما، آزاد) بخشی از شناسهٔ سری‌اند.
- تغییر رژیم یا منبع نرخ، با metadata و segment جدا ثبت می‌شود؛ تبدیل واحد، تعدیل بازده نیست.

### رمزارز
- هر صرافی و جفت‌ارز سری مستقل دارد.
- تغییر ticker، مهاجرت قرارداد، redenomination، token swap یا تغییر quote asset در instrument/event master ثبت می‌شود.
- تجمیع بین صرافی‌ها مرحله‌ای جداگانه و فقط پس از هم‌زمان‌سازی و کنترل اختلاف بازار است.

### جهانی
- سهام/ETF: split و dividend؛ futures: قرارداد و روش roll؛ شاخص‌ها: روش محاسبه و نسخهٔ شاخص.
- دادهٔ خام و adjusted ارائه‌دهنده هر دو نگهداری می‌شوند؛ روش vendor adjustment ثبت و sanity-check می‌شود.

## تصمیم فعلی
هیچ منبعی هنوز برای دریافت انبوه پذیرفته‌شده نیست. گام بعدی برای هر نامزد: آزمون کم‌حجم و فقط‌خواندنی endpoint، کنترل schema و بازه، بررسی محدودیت و مجوز، سپس ثبت در رجیستری. پس از آن adapter همان منبع در batch فعال می‌شود.
