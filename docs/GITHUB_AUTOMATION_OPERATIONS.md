# راهنمای اپراتوری زیرساخت خودکار MarketSage

## وضعیت این تغییر

این مستند و Workflowها در یک PR مستقل و Draft ارائه شده‌اند. تا پیش از ادغام انسانی در شاخه پیش‌فرض، Schedule و Recovery به‌صورت عملی فعال نیستند. این PR به‌تنهایی مجوز Merge، انتشار یا تغییر تنظیمات حساب نیست.

## خط مبنای ممیزی در ۲۰۲۶-۱۱-۲۰

- شاخه پیش‌فرض main در ممیزی جاری فاقد پوشه .github/workflows بود.
- API اجرای Schedule هیچ اجرای زمان‌بندی‌شده‌ای برای مخزن برنگرداند.
- تنها PR باز، PR شمارهٔ ۱ و در وضعیت Draft است؛ موضوع آن خط لولهٔ دادهٔ چندبازاری است و تا تکمیل Goal 1 متوقف می‌ماند.
- آخرین اجرای CI آن PR روی GitHub-hosted runner موفق بود؛ این شاهد Goal 1 محسوب نمی‌شود.
- مخزن در API رسمی GitHub با Visibility برابر public گزارش شده است. این تغییر Visibility را دست‌کاری نمی‌کند.
- وضعیت Branch Protection و Runner Registry از اتصال فعلی قابل تأیید نبود. هیچ ادعایی درباره فعال‌بودن حفاظت شاخه یا Runner مستقل مطرح نمی‌شود.
- مقادیر Secrets خوانده نشده‌اند. هیچ Secret یا Tokenی در فایل‌ها ثبت نمی‌شود.

## معماری پیشنهادی

1. Event-driven CI: Push به main یا شاخه‌های infra/** و Pull Request به main فقط تست‌های زیرساخت را اجرا می‌کند.
2. Scheduled watchdog: هر شش ساعت روی شاخه پیش‌فرض اجرا می‌شود و وضعیت آخرین اجراهای زیرساخت، صف‌های قدیمی، اجرای طولانی و تازگی Schedule را با GitHub API فقط‌خواندنی بررسی می‌کند.
3. Bounded recovery: فقط شکست یا timeout دو Workflow مجاز را بررسی می‌کند؛ فقط برای شاخهٔ همان مخزن و فقط وقتی run_attempt برابر ۱ باشد، یک بار Jobهای شکست‌خورده را دوباره اجرا می‌کند.
4. Timeout و cancellation: CI ده دقیقه، Watchdog هشت دقیقه و Recovery سه دقیقه سقف اجرا دارند. CIهای قدیمی همان ref با Concurrency لغو می‌شوند؛ Watchdog و Recovery اجرای فعال را لغو نمی‌کنند.
5. گزارش پاک‌سازی‌شده: فقط وضعیت کلی و شمارنده‌ها ثبت می‌شود. هیچ payload، داده بازار، شناسه دارایی، مسیر محلی، log خام یا Artifact آپلود نمی‌شود.
6. Human handoff: اگر صف بیش از ۲۰ دقیقه، اجرای فعال بیش از ۲۰ دقیقه، Job فعال بیش از ۱۲ دقیقه یا آخرین Schedule موفق بیش از ۸ ساعت عمر داشته باشد، Watchdog شکست می‌خورد و خلاصه پاک‌سازی‌شده می‌نویسد. لغو دستی فقط پس از بررسی Run ID و مالکیت آن انجام شود.

## مجوزها

| Workflow | مجوز |
|---|---|
| Infrastructure CI | contents: read |
| Watchdog | contents: read, actions: read |
| Recovery | فقط actions: write در Job محدود |

Recovery هیچ کدی از PR را checkout یا اجرا نمی‌کند و Artifactی را دانلود نمی‌کند. توکن موقت GitHub فقط از طریق متغیر محیطی به CLI داده می‌شود و هرگز چاپ یا ذخیره نمی‌شود.

## هزینه و محدودیت

- مخزن در زمان ممیزی عمومی است؛ GitHub-hosted standard runners برای مخازن عمومی طبق سیاست GitHub رایگان‌اند. تغییر آن به Private می‌تواند هزینه/سهمیه را تغییر دهد و خارج از این PR است.
- هر اجرای CI حداکثر ۱۰ دقیقه، Watchdog حداکثر ۸ دقیقه و Recovery حداکثر ۳ دقیقه مصرف می‌کند.
- Watchdog هر شش ساعت اجرا می‌شود؛ تأخیر یا حذف Schedule توسط GitHub ممکن است.
- اولین اجرای موفق Watchdog در حالت bootstrap_pending پذیرفته می‌شود؛ از اجرای بعدی تازگی Schedule سنجیده خواهد شد.
- این Watchdog نمی‌تواند خاموشی کامل سرویس زمان‌بندی GitHub را از بیرون تشخیص دهد؛ برای تضمین مستقل ۲۴/۷ به heartbeat خارجی در یک Failure Domain جداگانه نیاز است. چنین سرویسی هنوز پیکربندی نشده است.
- Runner خودمیزبان در این طرح فعال نیست. کارهای cloud-native روی GitHub-hosted اجرا می‌شوند.
- اگر بعداً Runner اختصاصی واقعاً لازم شد، باید روی میزبان مستقل، با حساب غیرمدیر، ثبت‌نام ephemeral، جداسازی VM/کانتینر، بدون دسترسی به Docker socket یا داده‌های حساس، بدون Jobهای PR ناشناس و با محدودیت خروجی شبکه طراحی شود. این مرحله هنوز انجام نشده است.

## عملیات اپراتوری

### شکست CI یا Watchdog
- ابتدا خلاصهٔ پاک‌سازی‌شده و Check شکست‌خورده را بررسی کنید.
- Recovery برای شکست/timeout واجد شرایط فقط یک بار retry می‌کند.
- اگر تلاش دوم نیز شکست خورد، علت را اصلاح کنید؛ Retry دستی متوالی یا افزایش نامحدود مصرف ممنوع است.

### اجرای صف‌شده یا گیرکرده
- GitHub-hosted runner باید با سقف Timeout خاتمه یابد.
- اگر Run بیش از آستانه صف ماند، Run ID را در Actions بررسی کنید.
- فقط اجرای تأییدشدهٔ همین مخزن و همین Workflow را لغو کنید:
  gh run cancel <RUN_ID> --repo yarsalam/marketsage
- هیچ Runner لپ‌تاپی را برای رفع صف روشن یا دائمی فرض نکنید.

### فعال‌سازی
- پس از بررسی انسانی، PR را فقط در صورت قبولی تمام Checkها و بررسی تنظیمات Branch Protection ادغام کنید.
- Schedule از شاخه پیش‌فرض اجرا می‌شود؛ تا پیش از ادغام این Workflow فعال نیست.
- پس از ادغام، یک اجرای Schedule واقعی، یک اجرای موفق Recovery، یک آزمون صف/Timeout و یک دوره مشاهده ۲۴ ساعته باید ثبت شود.
- هیچ Merge خودکار، Deploy، Production، Backtest، Scoring، Ranking، Broker/Trading یا تخصیص سرمایه در این معماری وجود ندارد.
